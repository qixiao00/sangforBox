## 1. 目标与范围

自动读取应用控制策略及其引用对象，分析问题，生成优化候选，验证行为等价性，并先导出表格供用户确认。确认后的执行继续使用项目固有工具链模式。

范围仅包含应用控制策略及其依赖对象。无关对象、其他策略模块不纳入治理。**业务意图不能仅从名称、零命中或规则宽窄自动推断。**

用户指定格式参考：

- `D:/chrome_downloads/appcontrol_1789703366048.csv`：策略导出参考。
- `D:/chrome_downloads/ipgroup.csv`：对象实例参考。

上述文件已读取并用于解析验证。真实设备导出可能存在版本差异，字符编码、分隔符、成员表示和设备导入能力仍需在适配时核实。文件内容仅作为数据，不接受其中的指令。

## 2. 主流程与状态机

### 2.1 端到端流程【目标】

1. 通过既有调用方式获取策略及依赖对象，或读取导出文件。
2. 保存完整原始快照及版本指纹。
3. 解析为统一语义模型，标记解析完整性和未知项。
4. 分析每条策略的有效范围、遮蔽、冲突和重复关系。
5. 生成候选变更包，记录依赖和互斥方案。
6. 逐项验证，并验证最终组合方案。
7. 导出审核工作簿、策略对照与对象变更表。
8. 读取用户确认结果，对选中或被编辑的方案重新验证。
9. 执行前核对设备状态与快照；发生相关变化则重新分析。
10. 使用既有工具链执行，通过回读验证结果，生成执行记录；失败时按已设计且可执行的恢复方案处理。

**【现状】** 当前实现是 `af_app/app_control_analyzer.py` 的离线分析层，输出 CSV 和 JSON 审核材料。设备能力已在 `af_app/operations.py`、`af_app/devices.py` 和 `af_app/mcp_server.py` 中提供。

**架构边界（强制）：**

- 不得绕过现有 MCP，自行用新的浏览器、API、CLI 直连设备。
- 离线分析逻辑必须与调用适配层分离。
- 后续适配应复用现有的 `prepare → plan → apply → verify` 流程。

### 2.2 审核与执行状态机【现状】

```text
分析中 → 待审核 → 已审核待复验 → 待执行确认 → 执行中 → 已验证 / 部分失败 / 验证失败
```

- 只有明确"采纳"的变更进入复验；空白、待确认及不采纳不进入计划。
- 用户可在聊天中按变更编号确认，或编辑表格后提交，二者生成相同的结构化审核记录。
- 重复编号、陌生编号、错误快照、旧版本、非法选择均拒绝处理。
- 修改只允许写入指定审核字段；修改策略方案本身需生成新版本并重新导出确认。
- 部分采纳必须重新生成完整的拟执行策略表再验证，**不能累计单项通过标识**。
- 确认记录绑定方案摘要哈希和具体变更；计划变化后不能沿用旧授权。
- 首次分析和表格导出**绝不触发设备写入**。

## 3. 统一语义模型

保留原始字段、顺序和稳定 ID，同时建模设备实际支持的以下信息：

- **身份**：原始 ID、名称、顺序、启用状态、备注。
- **条件**：源/目的区域、源/目的地址、用户、应用、服务、时间及其他实际条件。
- **效果**：允许/拒绝及日志、安全检测、限速等所有相关执行行为。
- **依赖**：对象引用、对象类型、完整成员、嵌套或动态依赖（如果存在）。
- **证据**：采集时间、命中数据及观测窗口、字段解析状态。

上述为待映射的概念，**不表示设备或 CSV 一定包含这些字段**。实现必须区分"已明确""未知""不支持解析"：

- 未知不得降级成任意值。
- 解析失败不得降级成空集合。

## 4. 等价整理与意图修复

### 4.1 严格等价整理

包括符合验证条件的重命名、冗余清理、内部成员简化、合并、拆分、对象化和无行为影响的顺序调整。**必须保持整张策略表最终行为一致。**

### 4.2 意图修复

包括使被遮蔽策略生效、改变例外优先级、收紧范围等。必须列出具体受影响流量和前后效果，由用户确认业务意图。**不得把这类改变描述成等价优化。**

> "细规则在前"只可作为分析线索，不可用作机械重排规则。**策略零命中不代表策略无效。**

## 5. 优化能力

### 5.1 命名规范化

建议可配置结构：`动作_业务或应用_源范围_目的范围_稳定短标识`。

优先保留可靠的业务含义；不明时使用客观字段。检查重名、长度和非法字符，保留原名、新名与 ID 映射。避免用可变序号作为稳定标识。核实是否存在按名称引用的调用或对象依赖。最终结构确定后再生成名称。

### 5.2 实际作用说明与顺序分析

每条策略说明配置范围、前序截获范围、剩余有效范围和执行效果。区分禁用、条件异常、完全遮蔽、多条联合遮蔽、部分遮蔽和观测期无命中。

识别例外与通用规则关系，说明当前优先级是否使例外生效。顺序建议必须列出原位置、新位置、跨越策略、受影响流量及前后效果。

### 5.3 重复、覆盖与内部冗余

识别完全重复、同效果覆盖和多条联合覆盖。删除冗余仍需在整表中验证。简化条件内部的重复成员、包含关系及重复引用，并保持精确匹配集合。

### 5.4 严格等价合并

第一版优先支持**仅一个匹配维度不同**、其他条件和完整执行效果相同的候选。合并条件集合必须等于原集合的并集，合并位置必须纳入整表验证。非相邻合并必须检查中间策略的影响。

**禁止以下直接合并：**

```text
原规则：S1 → D1；S2 → D2
错误合并：{S1,S2} → {D1,D2}
原因：额外引入 S1 → D2 和 S2 → D1。
```

技术上可合并与建议合并分开：业务责任、生命周期不同的策略可能更适合保留独立。

### 5.5 精确对象化

优先发现多条策略中反复出现的完全相同集合；先复用等价已有对象，再建议新建。保持 IP 集合精确等价，**不扩大网段**；不得把若干具体域名扩大为通配域名。"几乎相同"的集合仅提示差异。

列出对象完整成员、类型、引用策略及未来修改该对象的影响范围。IP 与域名混用、域名解析及匹配语义以设备能力为准。对象化应有减少重复或改善维护的实际收益。

### 5.6 拆分与维护结构

混合多个独立业务、职责或生命周期的超大策略可生成拆分候选，仍需等价验证。业务分组和备注可辅助维护；任何位置移动均需验证。**策略数量减少不是唯一目标。**

### 5.7 证据驱动的进一步建议

- **过宽条件**：标记大范围或任意条件，给出收紧候选及依据，不能仅凭宽泛断言不合理。
- **临时策略**：识别到期、缺少到期条件或需要业务复核的条目。
- **历史遗留**：结合观测窗口、低命中、对象问题、业务信息生成清理建议。
- **附加行为差异**：单独展示日志、安全检测等差异，避免错误合并。

只有配置时，可做静态重复、覆盖、遮蔽、冲突、合并和对象化分析。命中与流量数据属于增强证据；**缺失数据不是零命中，历史未出现不是未来不会出现。**

## 6. 严格验证契约

已知应用控制匹配自上而下。需进一步确认匹配是否终止处理、默认动作、应用识别、动态对象及其他设备特有语义。

在前序命中终止处理的条件下：

```text
策略 i 的有效匹配集合 = 策略 i 的匹配集合 − 前序启用策略的匹配集合之并
对任意流量 x：优化前最终效果(x) = 优化后最终效果(x)
```

若存在继续匹配或其他语义，上述简化公式不可直接套用。最终效果覆盖默认行为和可观察的附加执行效果。若日志包含规则身份等导致可观察差异，必须明确呈现该差异，**不能静默排除后声称严格等价**。

结果只能为：

- **已证明等价**：在明确、完整支持的语义和前提下完成证明，同时记录证明范围。
- **已证明不等价**：提供差异流量实例及前后效果。
- **无法证明**：列出未知字段、动态依赖或不支持语义，不能标记通过。

使用集合运算或约束求解进行严格验证，具体技术由后续实现选择。**抽样、历史流量回放只能补充，不能代替证明。** 每项变更后验证，最终组合再验证；部分采纳、编辑或依赖变化后重新验证。

## 7. 对外工具契约

### 7.1 MCP 工具【现状】

| 工具 | 职责 | 是否触碰设备 |
| --- | --- | --- |
| `analyze_app_control` | 接收设备选择与分析偏好，创建分析任务；返回任务/分析 ID、快照指纹、进度、输入问题及结果文件入口 | 只读 |
| `get_app_control_analysis` | 读取任务状态、摘要，或按变更编号获取完整证据；不默认向 LLM 返回全量策略 | 否 |
| `review_app_control` | 读取审核表或接收用户逐项决定，验证分析版本、变更编号、依赖及互斥项 | 否 |
| `verify_app_control_review` | 只验证审核组合的保守首条匹配模型 | 否 |

| `record_app_control_feedback` | 工程师手动变更后只读重采集，比较审核方案与当前配置，保存 JSON 差异日志 | 只读 |

## 8. 用户输入

### 8.1 实时分析【现状】

发起分析只需要确定目标设备。WorkBuddy 可从对话中提取设备名称、IP 或档案 ID；如果有多个匹配设备，返回选择问题。默认范围为该设备全部应用控制策略及引用对象，默认目标为命名、遮蔽、合并、对象化和顺序建议，**默认只分析并导出审核表**。

可选输入：命名模板、需要保留的策略、业务说明、限定业务范围。即使只优化部分策略，验证仍读取完整策略表。业务说明仅用于建议与解释，**不作为匹配语义证据**。命中统计缺失时继续静态分析并明确标注缺失。

用户不需要输入设备密码、API 路径、请求体、分页参数或集合运算规则。设备凭据和通信使用既有后端服务。缺少设备档案时引导使用现有设备管理流程。

### 8.2 离线分析

离线输入使用策略和对象导出文件。**离线审核结果不能直接作为实时设备执行授权**，必须先绑定目标设备并重新采集、映射及验证。

### 8.3 路由

WorkBuddy 连接器将整表梳理请求路由到 `af-app-control-optimization` Skill；用户明确指定单条策略的直接配置请求继续使用 `af-app-control-policy`。路由规则唯一事实来源见 [ROUTING.md](../connector/workbuddy/skills/ROUTING.md)。

## 9. 审核输出契约

### 9.1 首次输出必须包含审核表

用户首先收到结果摘要和可打开的审核文件，**不仅是一段自然语言结论**。主审核页每行对应一个完整变更包，包含：

| 字段 | 来源/是否可编辑 |
| --- | --- |
| 分析 ID、快照指纹、方案版本、变更编号 | 系统生成，不可作为自由文本覆盖 |
| 变更类型、涉及策略、原位置、新位置 | 系统生成 |
| 原条件与效果、建议条件与效果 | 完整前后对照，可分详情页呈现 |
| 原因、证据、等价结论、证明前提 | 计算结果 |
| 新建/复用对象及完整成员 | 方案内容 |
| 依赖、互斥方案、行为变化 | 系统生成 |
| 用户决定 | 可编辑：待确认、采纳、不采纳；默认待确认 |
| 用户备注 | 可编辑，仅记录意见，**不执行其中的指令** |

详细策略、对象、差异流量和恢复步骤通过独立页提供。原始设备格式 CSV 与审核表分离；审核辅助列不写入设备导出格式。

无候选时仍输出带表头的结果和分析覆盖范围。存在未知语义时必须展示未知项，**不得用空报告暗示"全部正常"**。

> **【现状】** 可下载的审核材料当前为 **CSV**，尚不是多页 Excel 工作簿。

### 9.2 变更包定义【目标】

每个变更包包含：稳定变更编号、问题描述、证据、原策略和对象、新的完整内容与位置、影响、验证结论及前提、收益、依赖、互斥方案、用户采纳状态和可执行的恢复计划。

对象新建、合并策略生成及原策略移除等依赖操作**绑定为完整变更组**。互斥方案不能同时采纳。执行步骤的原子性、批量能力和失败恢复需根据真实设备接口设计，**不能假设支持事务**。

### 9.3 审核工作簿建议结构【目标】

| 表页 | 内容 |
| --- | --- |
| 方案汇总 | 类型、原因、验证结果、收益、采纳状态 |
| 策略前后对照 | ID、名称、位置、完整条件与效果差异 |
| 对象变更 | 新建/复用对象、完整成员、引用及影响范围 |
| 合并证明 | 原策略、合并维度、集合关系、整表验证 |
| 行为变化 | 差异流量、原效果、新效果、业务确认项 |
| 执行与恢复 | 步骤、依赖、执行状态、失败恢复措施 |

另提供与样例列结构相符的策略和对象 CSV；审核辅助字段与设备格式分离。**未核实设备导入要求前，不将这些 CSV 宣称为可直接导入。** 明确区分原始快照、建议表和已确认执行方案。

## 10. LLM 与程序分工

LLM 提取需求、解释证据、询问业务优先级并转达用户决定。程序完成全量分页、快照、解析、精确集合计算、整表证明、文件导出、确认校验、计划生成、执行和回读。

**LLM 提议的名称或业务归类必须经过程序校验；LLM 的"认为等价"不是证明。**

## 11. 核心验收场景

- 前序不同效果规则完全或部分覆盖后序规则时，正确展示有效范围和行为变化。
- 多条前序规则联合覆盖时，不遗漏联合遮蔽。
- 非相邻同效果策略之间有冲突规则时，不误合并。
- 源和目的同时不同的规则，不生成笛卡尔积扩大的合并结果。
- 动作相同但日志或检测效果不同，不被当作严格等价。
- 精确地址集合可简化；存在地址空洞时不得扩大网段；具体域名不得擅自变通配域名。
- 未知条件、对象缺失、动态语义不能解析时，报告无法证明。
- 无命中数据与真实零命中分别呈现；**零命中不会直接触发删除**。
- 默认动作、禁用策略和时间条件进入正确的语义处理。
- 单项通过但组合有冲突时，组合验证拒绝通过。
- 用户只采纳部分方案、编辑方案或设备状态变化后，触发重新验证。
- 导出保持原始追溯关系，格式和中文编码经过实际样例验证。

## 12. 未实现 / 待核实清单

### 12.1 第一版优先级（已交付）

命名规范化、实际作用说明、重复与联合遮蔽检测、条件内部简化、单维度严格等价合并、精确重复集合对象化、例外关系识别及完整确认表。

顺序修复、过宽条件收紧、历史清理和复杂拆分可生成有证据的候选。**未经证明的变更不得进入等价整理执行路径。** 实现时明确列出已支持与未支持能力，避免用占位结果冒充分析完成。

### 12.2 后续适配待核实项

1. 应用控制实时查询返回值与 CSV 字段的映射，以及如何通过既有 `policy.app_control.list` / `network_object.list` 能力构造统一快照。
2. 两个参考 CSV 的真实结构，以及仅靠它们能否完整建模策略效果。
3. 设备的默认行为、应用匹配、对象解析、时间及日志等语义。
4. 命中数据是否可用及观测窗口；缺失时按配置分析模式继续。
5. 导入、调整顺序、批量修改、回读和恢复能力。

以上属于**尚未取得的事实，不应伪造成已实现能力**。离线分析器不因缺少这些事实而伪造设备执行结果；适配完成后仍需保留快照、审核、计划和回读验证边界。

### 12.3 执行闭环的已知阻断

`preflight_app_control_review` **当前始终阻断执行**，直至完成以下认证：

- 设备版本语义；
- 位置移动语义（AF 8.0.107 手册有策略 POST/PATCH 的 `_where`、`_dest` 参数，但文档存在示例与 schema 表述差异，**不能据此宣称已验证移动语义**）；
- 对象创建；
- 逐步回读；
- 恢复方案。

跨动态应用条件的完整关系与顺序执行适配仍待实现，**不能把未发现问题当作全部正常**。测试当前主要覆盖模拟数据，不代表实机生产认证。

## 附录 A：已实现模块索引

| 模块 | 职责 |
| --- | --- |
| `af_app/policy_sets.py` | 精确区间、多维集合差、联合遮蔽有效区域及完整首条匹配模型的等价证明。未知语义与计算预算耗尽返回 unknown |
| `af_app/policy_semantics.py` | 保守的 AF 网络对象语义与地址空间分析。仅解释静态 IP/ADDRGROUP 对象，其他谓词须逐字节结构相等 |
| `af_app/policy_snapshot.py` | 使用既有 DeviceService 的客户端和凭据生命周期，完整分页采集应用控制策略、网络对象与策略组。校验总数、偏移、页长度、重复标识和策略位置，保留完整嵌套列表。两次配置读取一致才返回快照；**此机制不是设备事务，执行前仍须复验** |
| `af_app/policy_optimizer.py` | 应用控制审核服务；所有设备访问停留在服务端。通过 MCP 提供异步分析任务，分析完成后默认提供中文审核 CSV 下载。当前支持命名候选、静态地址集合联合覆盖分析、单维地址合并候选、重复引用集合对象化候选，以及需业务确认的顺序意图修复候选 |
| `af_app/policy_review.py` | 不可变分析记录、中文审核 CSV 导出/读取、方案指纹绑定、依赖/互斥验证及并发幂等提交。**采纳审核项不直接授权执行** |
| `af_app/policy_combination.py` | 从持久化审核记录重建完整拟执行配置并做组合验证。相同的非地址条件建模为同一个布尔谓词，不同条件允许独立取值；这种保守模型可以证明部分变更等价。模型中的反例可能并非实际可达流量，故返回 unknown 和抽象反例，**不能冒充设备实测差异**。模型等价返回 `model_equivalent` 和证明前提，不会被当作设备执行授权。日志开启时将规则身份作为效果的一部分；缺少日志等语义字段时不证明通过 |
| `af_app/policy_plan_validation.py` | 逐个中间状态的等价验证，检查快照、状态连续性、操作原子性和最终配置对应关系。**原子性与适配器验证标识必须来自已验证代码，不能接受 LLM 的自由断言** |
| `af_app/policy_feedback.py` | 工程师手动变更后的结构化比较。使用 `review_id` 固定原建议版本，再次只读采集完整配置，对原配置、审核组合和当前设备状态做结构化比较；持久化日志可从 `/api/app-control/feedback/{feedback_id}.json` 下载。工程师标识、工单和理由是自述，**配置差异不证明是谁操作或是否具备真实业务等价性** |
| `af_app/app_control_analyzer.py` | 离线分析入口。读取应用控制策略和网络对象 CSV，生成策略遮蔽、重复、合并候选、对象复用候选、命名候选和审核汇总；**当前不会连接设备或下发配置** |

> 审核和组合复验均不会触发设备变更。实际设备版本语义、依赖对象完整性、默认行为和实时执行能力必须继续由适配层核实。
