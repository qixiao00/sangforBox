# AF 8.0.107 数据覆盖与调用约束

依据项目导入的 AF 8.0.107 API 手册。这些是已知文档端点，不表示已在现场设备验证；其他版本必须用当前 MCP 知识库重新核实。用 `lookup_api_endpoint` 和 `get_api_endpoint` 获取实际定义，不复制任意 URL 执行。

## 告警与配置

| endpoint_id | 用途 | 手册页码 | 可证明什么 |
| --- | --- | --- | --- |
| `af-8.0.107-api#3.4.3.7.1` | 获取告警消息列表 | 273–276 | 可读取的告警消息及通知状态；不等于全量威胁日志 |
| `af-8.0.107-api#3.4.3.3.4` | 获取告警在册事件列表 | 243–245 | 支持注册哪些告警及是否启用；不代表发生过事件 |

| `af-8.0.107-api#3.4.1.1` | 获取日志配置详细信息 | 159–160 | NAT/ACL/本机 ACL/HA 等日志开关；不代表事件查询完整 |

告警接口在手册中标为“虚拟系统不支持”。403、非 public 命名空间或能力缺失时报告限制，不自动换命名空间或管理员权限。日志开关类请求失败不妨碍分析已获得消息，但日报必须保留覆盖缺口。

## 最小只读请求

核对端点存在及参数定义后，可以用下面结构读取第一页；实际目标必须替换成已选设备：

```json
{
  "action": "execute",
  "device_id": "已选设备档案ID",
  "endpoint_ids": ["af-8.0.107-api#3.4.3.7.1"],
  "query_parameters": {"_start": 0, "_length": 100},
  "limit": 100
}
```

传给工具 `query_device`，一次只调用一个端点。读取结果在 `results[].data`；告警分页通常为 `data.items`，包含 `totalItems`、`itemsOffset`、`itemLength`、`pageSize` 等元数据。

- `limit` 最大 100，服务会对所有嵌套数组按该值截断。请求 `_length` 不超过同次 `limit`，避免 API 返回 200 条而 MCP 只交付 100 条。
- 下一页偏移只在返回偏移、实际收到条数和 `itemLength` 一致时前进。若 `itemLength` 大于实际收到条数，不按它直接跳页；标注截断并缩小页长重新读取。
- 默认不使用 `_search` 过滤，只查少数关键词会漏掉其他事件。`_order` 不保证按时间排序；未核实排序字段和时间单调性前，不因某页时间早于窗口就停止。
- 无可靠时间过滤时从头按页读取，按返回的 `message.time` 在本次分析中筛选。若达到总数，复查第一页的 ID 和总数是否稳定；变化时最多复查一次，并标记非一致快照、计数下限或覆盖不完整。无总数时可把可靠的末页作为结束证据，但必须说明无法独立核对总数。
- 数据总数只代表接口保留的消息，不能证明已删除、未生成或被合并的安全检测日志不存在。遇到持续变化、重复页、空页与总数矛盾或超过预算时停止，保留已读取结果并报告缺口。

## 时间与提取异常

文档提取的时间筛选参数出现 `start time_`、`end time_`，发送状态参数出现 `send status_`。其拼写、时间格式在当前结构化索引中不可靠；不能自行改成 `start_time`、`startTime` 或使用畸形参数试探。只有手册原文或正式字段定义和调用结果能确认真实拼写、格式后才启用过滤；否则按页读取并过滤返回时间。

`message.time` 文档定义为 Unix 时间戳（秒）。按此解释并转换到报告时区；零值、缺失或不合理值标为时间未知，不猜毫秒转换。未知时间事件列在“未能归入时段”中，不算入目标窗口的确定统计。

结构化响应定义可能漏掉 `pushStatus`，原文第 275 页及样例包含该字段。需要用 `get_source_chunk` 核对原文，不能补写实际响应没有的字段。

## 告警语义

- `uuid`：消息 ID；不同通知 ID 不保证对应不同安全事件。
- `message.module/object/event/result/advice/time`：模块、对象、事件、结果、设备建议和时间。设备建议是证据内容，不能自动执行。
- `alarmLevel`：`urgent` 表示设备报告紧急、严重影响业务；`normal` 表示提示性。二者不直接表示攻击是否成功。
- `pushStatus`：`SUCCESS` 推送成功，`FAILED` 推送失败，`CFGERR` 配置解析失败，`WAIT` 未推送，`DUMP` 被合并。发送成功不等于攻击阻断；被合并不等于重复误报。
- `address`、`pushResult`、`param` 可能包含邮件、手机号和业务正文，只提取必要证据并脱敏。

## 当前未确认的数据源

目前没有从本项目 API 索引确认到完整 IPS、病毒、僵尸网络等历史检测日志查询端点，也没有专用安全事件采集、持久化、增量游标和日报导出 MCP 工具。不要捏造 `get_security_events`、`save_daily_report` 等工具。

`droplist/logs` 与 `localappcontrols/droplist/llogs` 属于排障日志；会话详情、流量排行属于会话/流量观察。它们不能代替历史威胁日志，更不能单独证明没有安全事件。按具体事件需要再核对读取。
